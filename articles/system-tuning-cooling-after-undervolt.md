# ケースの冷却を確かめてから、UVとファンの下限を詰める

GPUの電圧を下げる前に、まずケース側をどこまで詰められるか確かめておきたいと思いました。ファンも電圧も一度に変えると、何が効いたのか分からなくなります。先に吸排気を変えたときの温度を見て、その状態からGPUの発熱を減らしてみます。

AIOの故障をきっかけに、Define 7の中はすでに組み替えていました。前面吸気で使っていたKraken X73を外し、新しいKraken 360は天面排気へ。天面にあったNoctuaの140 mmファン3基は前面へ移しました。前面から入った外気を、そのままRTX 3080へ送る配置です。

ただ、配置を変えただけでは、どのファンがどれくらい効いているかは分かりません。FF14を回し、GPU、CPU、冷却水の温度と、それぞれのファン回転数を見ながら確かめることにしました。

## 底面から風を増やしてみる

最初はファン制御にも引っかかりました。底面のDynamic X2 GP-14は3ピンのDCファンなのに、PWM設定で使っていたため、カーブを変えても約900 RPMのままでした。DC Modeへ直して較正し、試験の前後に実際に使われるカーブを照合するようにしました。再起動で設定が戻る問題も、後で制御サービスを切り替えて解消しています。

ケースファンを全部GPU温度へ連動させたときは、背面が平均約1,455 RPM、前面が約1,353 RPMまで上がりました。さすがにこの回転数では音が気になります。前後のカーブを少しずつ下げてもGPUはほとんど熱くならなかったので、最初の設定は回しすぎていたようです。静音化は、この頃から何度か試しています。

その後、GPUの先端から前面ファンまで水平に導風板を入れました。底面から上がる風と前面下段から入る風を、GPUのファンが吸う方へ向けるつもりです。付け外しでHotspotが約0.7℃下がりました。1℃にも届きませんが、板一枚で少しでも下がるなら残しておきたい。今度はこの板を入れたまま、底面ファンを強くしてみました。

通常のカーブは、GPU温度40℃で38%、60℃で40%、75℃で65%。まずこれを60%／80%／100%へ上げると、GPU温度とHotspotが少し下がりました。ところが、一度通常へ戻しても同じくらい低いままです。これでは、強く回した意味があったのかよく分かりません。さらに80%／90%／100%まで上げ、最後は停止して比べました。

| 底面ファン | 回転数 | GPU平均温度 | Hotspot平均温度 |
| --- | ---: | ---: | ---: |
| 通常設定へ戻す：38%／40%／65% | 589 RPM | 66.68℃ | 82.37℃ |
| 増速：80%／90%／100% | 893 RPM | 66.99℃ | 82.22℃ |
| 全点0%の停止設定 | 停止時のRPMは取得できず | 66.69℃ | 82.52℃ |

表の三つの設定点は40／60／75℃です。温度と回転数はGPU使用率50%以上の区間から集計しました。この段階のGPUは低電圧化前で、負荷中に平均約340～350 W使っています。

約600 RPMから900 RPM近くまで上げたのに、GPUはほとんど冷えません。止めたときに至っては、通常回転との差が0.01℃です。このくらいなら、GPUを冷やすために底面を回しておく理由は見当たりませんでした。前面から入る風で間に合っているのかもしれません。

ただ、停止した回にはCPU/cache系の訂正済みWHEAが1件出ています。温度はほぼ同じでも、エラーが出たことは別に気になります。底面停止と関係があったのかは分からず、このあとも確認を続けています。

## 側面を開け、背面と天面も変えてみる

底面を止めたままサイドパネルを開けると、GPU平均温度は66.69℃から66.30℃、Hotspotは82.52℃から82.18℃でした。ケースを開けても0.4℃ほどしか下がりません。GPUのために側面を開けたまま使うほどの差ではなさそうです。

一方、CPUは平均で約4.3℃、冷却水も約2.1℃下がっています。こちらは気になります。測り始めの水温も1℃低かったので全部が側面を開けたおかげとは言えませんが、CPUと天面ラジエーターの方には、まだ試せることがありそうです。背面ファンは天面の排気を助けているのか、それとも風を取り合っているのか。側面を閉じ、今度は背面を停止指定してから100%まで回してみます。

| 背面ファン | 通常回転との違い | GPU平均温度の差 | Hotspot平均温度の差 |
| --- | --- | ---: | ---: |
| 停止指定 | GPUファンが約78 RPM増速 | ＋0.51℃ | ＋0.86℃ |
| 100% | 背面が約779→1,480 RPM | ＋0.20℃ | ＋0.32℃ |

背面を止めると、GPU温度が少し上がり、GPUファンも余分に回っています。底面とは少し違いました。ところが100%にして、回転数をほぼ倍にしても冷えません。これでは1,480 RPMまで回す甲斐がありません。

背面は普通に回しておくのがよさそうなので、元のカーブへ戻しました。停止指定の回は回転数をほとんど取れず、途中で本当に止まり続けていたかは分かりません。気になっていた背面と天面の風の取り合いも、はっきりした答えまでは出ませんでした。

続いて背面を通常へ戻し、天面ラジエーターを100%固定にしました。そのあと、ラジエーターをGPU温度で動かすことも考えましたが、それではCPUだけが忙しいときに追従しません。以前から使っていた冷却水温の連動を続け、そのカーブを詰めることにしました。ポンプも冷却水温を見るCAM標準のSilentを維持しています。

ラジエーターは100%固定を基準に、90%主体、70%主体と下げてみました。90%と70%のカーブは、水温45℃までその出力を保ち、50℃で100%になる設定です。

| ラジエーターファン | 開始水温 | 水温平均 | CPU平均 | GPU平均 |
| --- | ---: | ---: | ---: | ---: |
| 100%固定 | 33℃ | 35.58℃ | 57.80℃ | 66.71℃ |
| 90%主体 | 34℃ | 36.39℃ | 58.34℃ | 67.31℃ |
| 70%主体 | 35℃ | 37.38℃ | 60.23℃ | 66.86℃ |

100%と70%では、CPUが平均で約2.4℃違います。ただ、100%の回は最初から水温が2℃低いので、ファンを速くした分だけ冷えたとは言い切れません。GPUはどれでもほとんど同じです。

70%でFF14は回っていますし、もっと水温が上がればファンも100%へ向かって上がります。それなら、この辺で十分だと思いました。70%と90%を何時間も回して比べるところまではやらず、使っていて温度や音が気になったら、そのときに考えることにしました。

## ケース側を確かめたところで、GPUの発熱を減らす

底面ファンの回転数を上げても、背面を全開にしても、側面を開けても、GPUはほとんど冷えませんでした。もっと風を通せば冷えると思っていたのですが、今のケースはすでに必要な風を通せているようです。それが分かったので、次はRTX 3080のUV、低電圧化へ進みました。ここからはGPUが出す熱を減らしてみます。

最初は1905 MHz／825 mVを試しましたが、FF14の途中でDirectXエラーになりました。25 mV戻した1905 MHz／850 mVでは完走できたので、従来設定と比べます。どちらも4Kのカスタム設定で、DLSSの動的解像度は常時適用です。

| 項目 | 従来設定 | 1905 MHz／850 mV |
| --- | ---: | ---: |
| Score | 17,674 | 17,082 |
| GPU平均電力 | 350.7 W | 252.8 W |
| GPU平均温度 | 66.84℃ | 58.90℃ |
| Hotspot平均温度 | 83.42℃ | 73.56℃ |
| GPUファン1／2平均 | 1,776／1,774 RPM | 1,072／1,072 RPM |
| 背面ファン平均 | 771 RPM | 678 RPM |
| 前面ファン平均 | 775 RPM | 698 RPM |
| 冷却水平均温度 | 36.40℃ | 36.17℃ |

Scoreは約3.35%下がりましたが、GPUの電力は約98 W減りました。この3%と100 Wなら、自分の使い方では100 W下がる方を取りたいです。GPU温度も約8℃、Hotspotは約10℃下がっています。ケースファンをあれこれ変えていたときは1℃にも届かない差を見ていたので、これだけ変わるとUVを試した甲斐があります。

GPUファンも約1,800 RPMから1,100 RPMほどになりました。GPU温度を見ている前後のケースファンも一緒にゆっくり回るようになっています。温度が下がったうえに、冷やすために回していたファンまで落ち着いてきました。

ただ、水温を見ると、どちらも約36℃でほとんど動いていません。GPUほどは変わらないようです。CPUも冷えていますが、こちらはCPU自身の電力も約90 Wから79 Wへ減っていました。ケース内の空気の温度は測っていないので、CPUが冷えた理由はまだ分けられません。

## 水温が落ち着くまで2時間かかった

850 mVの単発結果はよかったのですが、長く回すと約59分で再起動しました。その前にはCPU/cache系のWHEAも出ていたため、CPUの最高倍率を全段100 MHz相当下げ、もう一度長時間試験を行っています。

今度は約3時間22分回しても、WHEAやGPUドライバの異常、再起動はありませんでした。GPUの設定にも違いがあるのでCPU倍率だけで直ったとは言えませんが、前は1時間持たなかったものが、3時間を超えて回っています。ラジエーターは70%主体、底面は停止設定のまま。GPUの平均電力は約252 Wでした。

| 経過時間 | 冷却水の平均温度 |
| --- | ---: |
| 開始から30分 | 41.50℃ |
| 30～60分 | 43.15℃ |
| 60～90分 | 44.00℃ |
| 90～120分 | 44.00℃ |
| 120～150分 | 44.94℃ |
| 150～180分 | 45.00℃ |

水温は37℃から始まり、約2時間かけて45℃まで上がりました。そのあと終了までは、ログに値が残っているところはずっと45℃です。最後の30分も変わっていません。整数℃の記録なので細かい上下は分かりませんが、熱がこもっていつまでも上がっていく様子はありませんでした。

CPUも温度や電力の制限にかからず動いています。CPUとGPUの安定性を確かめているうちに、水が温まりきっても今のファン設定で使えそうだと分かりました。ラジエーターを70%より強くする必要は、ここでも感じませんでした。

## 温度が低いときにも70%で回す必要はあるか

負荷中の水温を確認できた一方で、待機中はラジエーターの音が気になりました。それまでのカーブは水温20～45℃が70%なので、冷えているときにも70%で回ります。

そこで水温20～35℃を60%、40℃を65%へ下げました。45℃70%と50℃100%は維持しています。先ほど長く回したときの45℃では同じ出力になり、そこから水温が下がったところで回転を落とす形です。

その後はCore i9-10900Kでも、FF14に必要な性能を残しながら倍率と電圧を下げました。コア数と倍率を変えて測るうちに、10コアを使うなら40倍でも性能がかなり残ることが分かってきました。FF14中に主に使う倍率を50倍から40倍へ変えたときは、次の結果でした。

| 項目 | 主に50倍で動く設定 | 主に40倍で動く設定 |
| --- | ---: | ---: |
| Score | 17,611 | 16,871 |
| 対象倍率でのVcore中央値 | 1.412 V | 1.190 V |
| CPU平均電力 | 95.21 W | 55.83 W |
| CPU平均温度 | 65.90℃ | 58.20℃ |
| GPU平均電力 | 255.23 W | 254.23 W |

5 GHzから4 GHzへ下げても、Scoreは約4%しか落ちませんでした。CPUの電力は約95 Wから56 Wへ減り、温度も約8℃下がっています。FF14のために5 GHzで回し続けるのは、少しもったいなく思えてきました。

倍率表と自動電圧補正も変えているので、電圧を下げただけの結果ではありません。ただ、GPUの電力はほぼ同じなので、今回はCPU側で減らせた分がよく見えます。普段の操作用には高い倍率を残し、FF14で10コアを使うときは40倍にする方向で、さらに電圧を調整していきます。詳しい経緯は[CPU効率編](./system-tuning-2026-09-03-cpu-efficiency.md)に書いています。

別途、比較用の4K最高品質でも測り直しました。こちらはDLSSを60 FPS未満で適用する条件で、GPUは平均約278 W使っていました。前のカスタム設定では約253 Wだったので、描画設定を変えると電力も気になります。CPU・GPUの設定も途中で変わっており、増えた分を全部DLSSの違いとはできませんが、ファンを下げるなら、この278 W使っている方でも確かめておきたいと思いました。

## 前後のファンとラジエーターの下限をもう一段下げる

FF14を回しているときの温度は、ひとまずよさそうです。今度は待機中の音をもう少し抑えたくなりました。温度が下がっていても、ファンの設定が以前のままなら下限で回り続けます。せっかく発熱を減らしたのだから、冷えているときはもう少し回転を落としてみます。

| 対象 | 変更前 | 変更後 |
| --- | --- | --- |
| 背面ファン | 先頭点40℃31% | 30℃20% |
| 前面ファン | 先頭点40℃40% | 30℃20% |
| ラジエーター | 水温20～35℃60% | 同じ温度帯を35% |
| GPUファン1／2 | 先頭点30℃50% | 30℃30% |

背面はCPUとGPUの高い方、前面はGPU温度を見ます。前後とも60℃で40%となる点は残し、80℃では背面約59%、前面60%、さらに温度が上がったときの100%保護点も維持しました。上昇12秒・下降25秒の応答設定もそのままです。

ラジエーターは40℃65%、45℃70%、50℃以上100%を残しています。水温が45℃まで上がれば、3時間以上回したときと同じ70%になります。そこを変えずに済むなら、冷えているときの回転を下げやすいです。GPUも60℃50%、70℃82%、85℃100%の点はそのまま。ポンプは冷却水温を見るSilentのまま、底面も停止設定を続けました。

ラジエーターのカーブを並べると、変えたところが分かりやすくなります。

| 冷却水温 | ケース側を調べたあとの設定 | 最初の待機音調整 | もう一段下げた設定 |
| --- | ---: | ---: | ---: |
| 20～35℃ | 70% | 60% | 35% |
| 40℃ | 70% | 65% | 65% |
| 45℃ | 70% | 70% | 70% |
| 50℃以上 | 100% | 100% | 100% |

## 下限を下げたあとも、負荷中はほぼ同じだった

静かにするつもりで下げた分が、負荷中の冷却に影響していないかも見ておきます。同じ4K最高品質のFF14をもう一度回しました。

| 項目 | 下限変更前 | 変更後 |
| --- | ---: | ---: |
| Score | 10,845 | 10,820 |
| 平均FPS | 75.101 | 74.946 |
| CPU最高温度 | 65℃ | 62℃ |
| GPU最高温度 | 66.4℃ | 66.6℃ |
| Hotspot最高温度 | 81.1℃ | 80.0℃ |
| 冷却水温・開始→終了 | 36→40℃ | 36→40℃ |
| 背面ファン平均 | 722 RPM | 724 RPM |
| 前面ファン平均 | 726 RPM | 712 RPM |
| GPUファン1／2平均 | 1,272／1,272 RPM | 1,279／1,278 RPM |

負荷をかけると、前後のファンは平均700 RPM台、GPUファンは平均約1,280 RPMで回っていました。前とほとんど同じです。水温も同じ36℃から40℃まで上がり、GPUの最高温度も0.2℃しか違いません。心配していた、回転を下げたせいで熱くなるということはなさそうでした。

Scoreの差も、1万点を超える中で25点。平均FPSは75.101から74.946です。この差を気にしてファンを元へ戻すほどではないので、下げた設定を使うことにしました。CPUの最高温度は3℃下がっていますが、電圧設定とGPUクロックも変えているので、そこまでファンのおかげにはできません。

後の短いブラウザ試験では、水温34℃、GPU平均33.6℃で、背面が平均472 RPM、前面が374 RPMでした。前面3基のうち測れているのは1基ですが、FF14のときの700 RPM台からは随分下がっています。ゲームを回していないときまで、同じ勢いで回る必要はなさそうです。

GPUの方は、30%に設定したのに、このブラウザ試験では実測50%、約857 RPMでした。設定を下げた分だけ回転も落ちる、とはいかなかったようです。

## さらにGPUの電圧を下げると、同じカーブでも回転数が下がった

ファンの下限を下げたあとも、CPUとGPUの調整は続けています。GPUを1740 MHz／800 mVから1620 MHz／750 mVへ下げた単発比較では、同じ4K最高品質で次のようになりました。

| 項目 | 1740 MHz／800 mV設定 | 1620 MHz／750 mV設定 |
| --- | ---: | ---: |
| Score | 10,680 | 10,611 |
| GPU平均電力 | 235.71 W | 207.68 W |
| GPU平均温度 | 60.47℃ | 59.28℃ |
| GPUファン1／2平均 | 985／990 RPM | 880／888 RPM |
| 背面／前面ファン平均 | 700／683 RPM | 687／667 RPM |
| 冷却水温・開始→終了 | 36→37℃ | 36→37℃ |

表のクロックと電圧は保存設定で、実測は平均1763→1650 MHz、電圧793.75→750 mVでした。Scoreは69点、約0.65%しか違わないのに、GPUの電力はもう28 W減っています。これなら750 mVの方をもう少し試してみたくなります。

ファンのカーブはそのままですが、GPUファンは1,000 RPM近くから900 RPMを切るくらいになりました。前後のファンは十数RPMの差で、こちらはほとんど同じです。GPUは発熱が減った分、同じカーブでもゆっくり回るようになりました。

この二つの試験では、GPUファンが50%を下回る値も出ていました。先のブラウザ試験で50%だっただけでは、そこが下限だとは決められないようです。ここも、設定した数字と実際の動きを見比べていく必要がありそうです。

## ベンチ中の音も、以前の記録と比べてみる

その後はDLSSを常時適用し、Preset Kを指定して長時間ベンチを回しています。2時間経過後にリアファン横で測った音を、UV前に同じ場所で測ったベンチ中の記録と比べてみます。

| 騒音アプリの表示 | ファンの初期調整中・UV前 | 現在のベンチを2時間回したあと |
| --- | ---: | ---: |
| AVG（平均表示） | 52.5 dB | 43.3 dB |
| MAX（最大表示） | 56.2 dB | 45.9 dB |
| 画面の時間表示 | 1分22秒 | 15秒 |

時間表示の異なる2回の記録を並べると、アプリのAVG表示は以前より約9 dB低い値になっていました。
