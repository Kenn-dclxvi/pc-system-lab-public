# 2026年 自作PCチューニング記録

2026年、自作PCのAIO故障をきっかけに冷却系を見直し始めました。

最初はAIOを直して、ついでにケースファンを整理するくらいのつもりでした。ところが実際に温度や回転数を測り始めると、ケース内の空気の流れ、RTX 3080の約350 Wという発熱、長時間負荷で出るCPUのWHEAと、次々に別の課題が見えてきました。

その結果、作業はケース冷却からGPUのV/F調整へ、さらにCore i9-10900KのTurbo、TVB、Adaptive Voltage、V/F Curveの見直しまで広がりました。

今回、5年前と大きく違ったのは、AIエージェントを使って進めたことです。

設定の意味を調べるだけではなく、測定前の条件確認、ログの収集、過去の試験との比較、WHEAやWindows Event Logの確認、次に試す条件の整理まで一緒に回しました。どれも人間だけでできる作業ですが、毎回全部やるにはかなり重いです。今回はその部分を任せられたので、「気になるけど、調べるのが大変だからここで終わり」がかなり減りました。

この記録は、設定値の一覧ではなく、**何が気になって、何を測って、どう判断して次へ進んだか**をまとめたものです。最初の3本とエピローグに加え、その後に評価軸がワット当たり性能へ変わった続編と、完成したPCの実力を4K最高品質で見直した記事を追加しました。各記事には、その場面でAIエージェントをどう使ったかも必要な範囲で残しています。

既存の通史 `system-tuning-history-through-2026-08-30.md` は当時の記録としてそのまま残しています。こちらは2026年9月1日時点から振り返り、読み物として再構成した版です。

## 1. ケース・冷却編

### [AIO故障から、必要な分だけ回す冷却へ](./system-tuning-2026-09-01-case-cooling.md)

AIO故障をきっかけに、ケースファンと水冷系を一度全部見直しました。

Rearを100%まで回して上限を測り、Bottomは止めてもGPU温度がほとんど変わらないことを確認し、KrakenはCPU温度ではなくLiquid温度を見る構成へ整理しました。

テーマは、**強く回すことではなく、必要な冷却を保てるところまで回転数を下げること**です。

## 2. GPU編

### [約3%の性能と引き換えに、RTX 3080の消費電力を約100 W下げる](./system-tuning-2026-09-01-gpu.md)

FF14のスコア低下を冷却と切り分け、Hypervisor / VBSの影響を確認したあと、RTX 3080のV/F Curveを調整しました。

1905 MHz / 825 mVは失敗。850 mVへ戻すと短期ベンチは安定し、Scoreは約3.35%下がる一方で平均GPU Powerは約98 W下がりました。

ただ、長時間試験は59分で落ち、その前にはCPU/cache系のWHEAも出ていました。

## 3. CPU・BIOS編

### [5.3 GHzを追うところから、5 GHzを実用域にするところへ](./system-tuning-2026-09-01-cpu-bios.md)

長時間試験のWHEAを受けて、まずTurbo Ratioを全段1bin下げて安定性を確認しました。

そこからIntel本来のTurbo / TVB動作を調べ、5.3 GHzがPreferred Coreの限定的な動作点だと確認。Adaptive VoltageとV/F Pointを実測し、ASUS Overclocking TVB +1も試しました。最終的には5.3 / 5.4 GHzを追うのをやめ、4～10コア使用時を5.0 GHzにし、その5.0 GHz付近のV/F Pointを下げる方向へ切り替えました。

現時点では、5.0 GHzを全10コアで使いながら、平均CPU PowerをManual 1.300 V時の85.00 Wから81.25 Wまで下げています。

ケース、GPU、CPUの3本を通して、今回どこまで細かく試せたのかを最後に振り返ります。

## 続編

### [最適なコア数を探すところから、FF14で使う電力を選ぶところへ](./system-tuning-2026-09-03-cpu-efficiency.md)

当初はFF14に効く物理コア数を探し、そのコアを高く回すつもりでした。ところが6コア、10コアで性能曲線を下方向へ測るうちに、目標は最高Scoreからワット当たり性能へ変わっていきます。

6コアで性能低下が目立ち始めた42倍付近、10コアなら40倍まで実用性能を維持できたこと、通常操作用の52 / 50倍との統合、全体offsetで起きた長時間WHEA、倍率帯ごとに分けたV/F Point、90 Wの電力上限を経て、現在のCPU基本設定へ到達するまでをまとめています。

## もう一つの後日談

### [FF14ベンチマークを4K最高品質で回し、このPCの実力を測り直す](./system-tuning-2026-09-03-ffxiv-maximum-quality.md)

実際に使うためのカスタム設定とは別に、公開結果と比べやすい4K最高品質で現在のPCを測りました。Score 10,845が公開例のどの位置に入るのか、CPUとGPUを合わせた電力が以前の同じベンチ設定からどれだけ変わったのかを見直します。

同じベンチ設定の記録を残していたことで、性能を大きく崩さずにCPU+GPU合計平均電力を約30%下げられたことまで確認できました。

## 読む順番

各記事は独立して読めますが、通して読むと次の流れになります。

**AIO故障 → 冷却系を測る → GPUの消費電力を約100 W下げる → 長時間試験でCPU側の不安定性を発見 → CPUの最高倍率を100 MHz下げて長時間安定を確認 → 5.3 GHzの動作条件とV/Fを調べる → 5.3 / 5.4 GHzを追うのをやめ、4～10コア使用時を5.0 GHzにする → FF14で実際に使う倍率を測る → 最高Scoreからワット当たり性能へ評価軸を変える → 倍率帯ごとの電圧と90 W上限を組み合わせる → 4K最高品質で現在の実力を公開結果と比べる**

最初から5 GHzを狙っていたわけではありません。

ひとつの問題を測って片付けるたびに、次に見るべき場所が出てきた結果、ここまで広がりました。

最初の3本とエピローグは2026年9月1日時点の区切りです。そのあとに続編を読むと、そこで残っていたCPU調整が現在の基本設定へどうつながり、その設定が4K最高品質でどの程度の実力を残したのかまで追えます。
