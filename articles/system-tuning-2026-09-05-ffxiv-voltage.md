# ファンを静かにしたあと、CPU電圧をもう一度詰める

[← 4K最高品質編](./system-tuning-2026-09-03-ffxiv-maximum-quality.md) / [索引](./system-tuning-2026-09-01-index.md) / [固定電圧・Ring編 →](./system-tuning-2026-09-05-manual-voltage-ring.md)

待機中の音をもう少し下げたくなり、ファンの低温側を調整しました。

前回のFF14ベンチマークは4K・最高品質でScore 10,845。普段の使い方に合わせてCPUとGPUを調整し、負荷中の温度も確認できていたので、今度は待機中に回しすぎているところを抑えます。静かにした分だけ負荷中に熱くなっていないかも確認したかったので、同じFF14を1回回して温度と回転数を測ることにしました。

CPUのCore i9-10900Kには、電圧をまだ詰められていないところがありました。10コアを使うFF14では4.0 GHz、普段の操作では5.0 GHzや5.2 GHzも使う倍率表にしていましたが、それぞれの電圧をどこまで下げられるかは途中のままです。

ファン調整後の確認として始めた計測でしたが、その結果を前回と比べたところで、CPUのVcoreが気になりました。

## 負荷をかけると、ファンは前と同じくらい回っていた

変更したのは、ケースの前後、ラジエーター、GPUファンの低温側です。

| ファン | 変更前 | 変更後 |
| --- | --- | --- |
| Rear | 先頭点40℃・31% | 30℃・20% |
| Front | 先頭点40℃・40% | 30℃・20% |
| Krakenのラジエーター | 冷却水20～35℃で60% | 同じ温度帯で35% |
| GPU Fan 1 / 2 | 先頭点30℃・50% | 30℃・30% |

それより上のカーブは維持しました。ラジエーターは以前から冷却水温を見ており、40℃で65%、45℃で70%、50℃以上で100%です。ポンプも冷却水温を参照するSilentのまま。Bottomファンは、前から停止させていた状態を続けています。

設定を確認すると、ほかにも前回との差がありました。CPUのV/F Point 3・4は−80 mVから−100 mVへ、GPUの保存カーブは850 mV以上で1890 MHzだったところが1905 MHzになっていました。

FF14は黄金のレガシーベンチマークVer. 1.1、3840×2160、最高品質、仮想フルスクリーン、DirectX 11。DLSSと動的解像度を有効にし、60 FPS未満で適用、解像度スケール100%という前回と同じ設定です。

| 項目 | 前回 | ファン調整後 |
| --- | ---: | ---: |
| Score | 10,845 | 10,820 |
| 平均FPS | 75.101 | 74.946 |
| CPU最高温度 | 65℃ | 62℃ |
| GPU最高温度 | 66.4℃ | 66.6℃ |
| GPU Hotspot最高温度 | 81.1℃ | 80.0℃ |
| 冷却水温・開始→終了 | 36→40℃ | 36→40℃ |
| Rear平均回転数 | 722 RPM | 724 RPM |
| Front平均回転数 | 726 RPM | 712 RPM |
| GPU Fan 1 / 2平均回転数 | 1272 / 1272 RPM | 1279 / 1278 RPM |

負荷中の温度も回転数も前とほぼ同じで、Scoreもほとんど変わりません。これならファンはこの設定でよさそうです。

## 20 mV下げたはずなのに、Vcoreが同じ

40倍の電圧については、別のチャットでも相談していました。以前、CPU全体へ−100 mVのオフセットをかけたときには、40倍のVcoreが約1.08 VでFF14を1回完走しています。その結果を見て、1.05 Vくらいまで下げられないかと考えていました。

相談ではChatGPTのポイント番号の説明がはっきりしなかったので、ASUSの資料で調べ直してもらいました。4.0 GHzは、Point 3の3.5 GHzとPoint 4の4.3 GHzの間にあります。片方だけ深く下げる案も出ましたが、素直に3・4をペアで設定することにしました。

そこまで下げられれば、消費電力も減りそうです。ただ、CPU側を詰めても、全体ではGPUの発熱に隠れそうだとも思っていました。

で、ファン調整後の結果を前回と見比べていて、気になったのがこの40倍の電圧でした。

V/F Point 3・4は、前回から20 mV下げています。それなのに、40倍が観測された時刻のVcore中央値は、両方とも1.172172 V。VIDの中央値も1.173828 Vから1.175781 Vで、下がっていません。

まず、40倍に対応するポイントを間違えていないかと思い、今度はBIOS画面を確認しました。Point 3は3.5 GHz、Point 4は4.3 GHz。相談したときの対応と同じで、両方を同じだけ下げる選び方は合っていそうです。

さらに10 mV下げたときの反応を見るため、Point 3・4を−110 mVにして、FF14をもう1回測りました。Scoreは10,870でしたが、40倍のVcore中央値はまた1.172172 V。VIDも下がりませんでした。

| Point 3 / 4 | 40倍時のVcore中央値 | FF14のScore |
| --- | ---: | ---: |
| −80 mV | 1.172172 V | 10,845 |
| −100 mV | 1.172172 V | 10,820 |
| −110 mV | 1.172172 V | 10,870 |

何かほかの自動制御に影響されているのではないかと考えました。

## 下のポイントとTVBを試すが、すぐには分からない

最初に試したのは、Autoのまま残していたPoint 1・2でした。下のポイントが高いままでは、上のポイントを下げても電圧が下がらないのではないかと考え、Point 1～4をまとめて−100 mVにしました。

このときPoint 3・4は−110から−100 mVへ戻しています。Codexからは、二つの変更を含むので切り分けられないという説明がありました。ただ、元の−80 mVと比べることもできます。ここでは下のポイントを変えたときに電圧が動くかを見られればよいと考え、そのまま試しました。

毎回FF14を回すより、以前5.3 GHzの確認に使ったものと同系統の負荷を、10コアへかける方が早そうです。9コア以下へ減らしたときの倍率変動も一緒に見たかったので、10コアから1コアまで順に負荷をかけました。

ただ、これが思ったほど簡単ではありませんでした。CPUだけへ強く負荷をかけると、前に入れた90 Wの制限に達して37倍へ下がります。負荷を軽くすると40倍も測れ、Vcoreは約1.101 Vでした。FF14のときよりは下がりましたが、予想していたほどではありませんでした。

ここで以前のFF14も見返しました。CPU全体へかけるオフセットを−60から−80 mVへ変えたときは、40倍のVcore中央値が1.127771 Vから1.110011 Vへ約17.8 mV下がっています。ポイント設定の−80、−100、−110 mVでは1.172172 Vのままだったので、以前ほど下がっていないという感覚は合っていました。

次に気になったのは、TVB Voltage Optimizationsです。自動補正が電圧にどう影響しているかを見るため、ほかのV/F設定を維持してOFFにすると、50倍と52倍のVIDは上がりました。さらにPoint 1～7を20 mVずつ下げると、50倍のVIDや1コア52倍のVcoreには、それに近い下がり方が出ました。

こちらの方が素直に調整できそうにも見えました。ただ、肝心の40倍が取れない試験があり、10コアだけでもう一度測ることになりました。

その比較では、計算の間違いもありました。共有のVcoreを、その時刻に40倍だったコアの数だけ数えていたため、倍率の混ざり方によって平均や中央値が変わっていたのです。最初はこの集計をもとに、設定を下げたあとの方が実測値は高いと説明されました。同じ時刻のVcoreを一つとして数え直すと、中央値は1.181052 Vから1.163292 Vへ下がっていました。TVB ON側と以前のFF14も、同じ数え方で再集計しています。

途中で負荷率や測定時間も変わり、比べる条件が揃わなくなっていました。

普段はTVBの電圧最適化を使うつもりなので、ONへ戻しました。まずは全コア40倍で、同じ負荷なら同じくらいの電圧になるところから見直します。負荷の調整では40倍を保ちにくかったため、電力制限はいったん解除しました。

全コア40倍、TVB ON、Point 1～4が−100 mVで、30秒の負荷を3回。3回の平均Vcoreをさらに平均すると1.175557 Vでした。Point 1～4だけを−110 mVへ変えた次の3回は1.176032 V。差は約＋0.5 mVで、ここでも設定した−10 mVの低下は見えません。

倍率を揃えても電圧が変わらなかったので、ポイントを下げ続ける前に、そもそもこのCPUが40倍で何Vなら動くのかを知りたくなりました。
