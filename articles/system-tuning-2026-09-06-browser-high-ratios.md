# 52倍を戻す前に、ブラウザで高倍率の出番を調べる

[← FF14長時間試験編](./system-tuning-2026-09-06-ffxiv-long-run.md) / [索引](./system-tuning-2026-09-01-index.md) / [ブラウザ倍率比較編 →](./system-tuning-2026-09-07-browser-ratio-balance.md)

50倍と40倍を使い分けた設定で、FF14が2時間を超えて回りました。次は残していた52倍、と進む前に、ちょっと迷いが出てきました。

50倍で9コアへ負荷をかけたときにも分かったように、高クロックで複数コアを動かすと、電圧も電力も必要です。52倍を4コアまで使う設定は、このPCで出せる上の方の性能だと思っています。ただ、その負担に見合うだけ速くなるのでしょうか。

電圧調整前の52倍入りの設定へ戻すか、51倍や52倍を使うコア数から考え直すか。先にそこを確かめたくなりました。

## 高倍率を使わせたいわけではない

最初にCodexから出たのは、1～2コアだけ52倍を残す案でした。ただ、2コア用の倍率は、以前から設定しても使われている形跡があまりありません。

そう伝えると、今度は51倍を使う範囲を広げる話になりました。いや、気になっているのは、50倍以上で必要になる電圧と電力の方です。高倍率を使う機会を増やせばよい、という話ではありません。得られる性能との釣り合いを見て決めたいのでした。

新しく測る案も出ましたが、倍率ごとの電圧やブラウザを使ったときの記録は、すでにあります。まずそれを見てもらいました。

以前のFF14では、50倍から48倍へ下げても性能はあまり変わらず、CPUの電力はかなり減っていました。ブラウザの記録も、仕事の中心は少数コアなのに、軽い処理はほかのコアへ広がっています。52倍を2コアだけに置くより、よく使う中間の倍率から見直す方がよさそうです。

そこで候補になったのが、1～4コア51倍、5～6コア50倍、7～9コア49倍、10コア40倍という配分でした。

まずは今の設定でブラウザを測り、そのあとで候補へ変えて比較します。今の結果を見たら、候補の方を変えたくなるかもしれません。

## ブラウザでは、50倍でもそこまで重くない

この時点の設定は、1～9コア50倍、10コア40倍。Ringは40倍、AC Load Lineは0.300 mΩ、電圧はAutoです。V/F Pointは7だけ−80 mVで、ほかはAutoのままです。

普段のChromeと常駐ソフトを動かした状態で、5ページの移動、長文のスクロール、5タブの展開と操作を3回繰り返しました。

待機や操作の間を含む約11分の記録では、CPU電力は平均37.2 W、最大56.5 W。タブをまとめて開くところでも、平均44～48 Wほどでした。50倍は実際に観測されていますが、CPUだけへ強く負荷をかけたときとは随分違います。

これなら、50倍という数字だけで重いと考えるのも違いそうです。実際にブラウザを使ったときの性能と電力で比べることにしました。

使ったコア数も見たくなりました。最初は1～4コアなどとまとめて出てきましたが、それではどこで倍率を区切ればよいか分かりません。1～10コアまで、一つずつ出し直してもらいました。

操作中の約371秒を、約260 msごとに区切って数えた結果です。ここでは、ごく小さな活動も含めています。

| 区間中に動いたコア数 | 操作時間に占める割合 |
| --- | ---: |
| 1 | 0.14% |
| 2 | 0.98% |
| 3 | 1.60% |
| 4 | 1.27% |
| 5 | 3.13% |
| 6 | 5.49% |
| 7 | 6.41% |
| 8 | 9.76% |
| 9 | 18.47% |
| 10 | 52.68% |

どのコアにも活動がなかった区間は0.07%でした。細かい仕事まで数えると、かなり多くのコアへ広がっています。

物理コアごとの偏りも調べました。Core1とCore2が3回とも上位で、操作中の平均稼働率は18.7%と14.0%。ほかのコアも動いていますが、均等というわけではありません。

常駐ソフトの使うコアを少しまとめた方がよいのか、とも思いました。ただ、その効果を比べるにしても、ブラウザがどれだけ速くなったかを見るものが必要です。

今回のページ移動やスクロールには、通信や自動操作で待った時間も入っています。電力とコアの動きは見られましたが、その時間だけでは、倍率を変えて何%速くなったのかまでは分かりませんでした。

## ブラウザの性能も一緒に測る

そこで、測定環境を整えることにしました。使うのは[Speedometer 3.1](https://browserbench.org/Speedometer3.1/)です。Webアプリを操作したときの応答を測るベンチマークで、これならスコアとCPU・GPUの消費電力量を一緒に比べられます。

準備も一度では済みませんでした。先のブラウザ操作の集計では、時刻の変換を間違えて9時間ずれたものができ、元の操作ログから直しています。Speedometerの最初の起動では、コアの活動を記録する処理が先に止まり、ベンチを始められませんでした。

起動順を直すと完走しましたが、今度は終了時に画面が前面にあったかの記録が引っかかりました。調べると、テスト用の画面が片付けられたあとを見ていたので、最後の処理直後と片付けたあとを分けて記録するようにしました。

これで比較へ進めます。全20種類のテストを10反復し、暖機1回のあとに本測定を3回。Chromeの普段の環境を使い、倍率と電圧だけでなく、1～10コアの活動分布も残します。

まずは1～9コア50倍のまま測りました。スコアは16.245、15.989、15.711で、中央値は15.989。CPU電力量の中央値は1回20.239 kJでした。これを最初の比較相手にします。

## 7～9コアを49倍へ下げても、あまり変わらない

いきなり候補の倍率表全部へ変える前に、7～9コアだけを50倍から49倍へ下げました。1～6コアは50倍、10コアは40倍です。

| 本測定3回の中央値 | 1～9コア50倍 | 7～9コアだけ49倍へ |
| --- | ---: | ---: |
| スコア | 15.989 | 16.374 |
| CPU電力量／回 | 20.239 kJ | 19.899 kJ |
| CPU＋GPU電力量／回 | 52.927 kJ | 52.787 kJ |

性能は落ちておらず、CPUの電力量も少し減っています。ただ、3回の振れもあるし、どちらを選ぶかがはっきりするような差ではありません。

これは悩ましいねぇ。

積極的に下げる理由も、50倍を維持する理由も、今回の数字ではあまりありません。それでも、9コアまで50倍を支える必要がなくなった分、50倍や49倍の電圧を下げる余地は増えたのでは、と思いました。私にはそこが一番の収穫に見えました。

そう考えると、次に4コアまでの倍率を上げることには、あまり得を感じなくなってきました。それでも、高クロックにしたときの性能は見たい。予定どおり、1～4コアだけを51倍へ変えてみます。

## 4コアまで51倍にしても、出番がほとんどない

今度は、1～4コア51倍、5～6コア50倍、7～9コア49倍、10コア40倍です。

| 本測定3回の中央値 | 1～6コア50倍 | 1～4コアだけ51倍へ |
| --- | ---: | ---: |
| スコア | 16.374 | 16.308 |
| CPU電力量／回 | 19.899 kJ | 19.455 kJ |
| CPU＋GPU電力量／回 | 52.787 kJ | 53.580 kJ |

スコアはほぼ同じでした。倍率の記録を見ると、活動のあるコアで51倍が出たのは、1,140回の更新中に1回だけです。

4つでも使われないのか。この状態で52倍を試しても、しょうがないんじゃないかと思いました。

ブラウザは軽い作業の代表だと思っています。それでも4コア以下の高倍率にほとんど入らないなら、普段は何をしたときに使えるのだろう。中心となる処理が少数コアでも、常駐ソフトなどがほかのコアを少しずつ動かしている様子は、先ほどの記録にも出ていました。

瞬間的な用途や気分として、高倍率は残してもよいと思っています。ただ、その前に、50倍を使う範囲自体も多すぎるのかもしれません。

FF14のときと同じように、下げながら加減を探したくなりました。ところが、今の測り方では1設定に約1時間かかります。

候補を探すだけで、これはちょっと長い。まずは5分以内で測れる方法を作ってもらうことにしました。
