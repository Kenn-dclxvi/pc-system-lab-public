# DirectXエラーが続いたので、全コア40倍からやり直す

[← 高倍率・WHEA編](./system-tuning-2026-09-05-high-ratio-whea.md) / [索引](./system-tuning-2026-09-01-index.md) / [ブラウザ高倍率編 →](./system-tuning-2026-09-06-browser-high-ratios.md)

FF14の長時間試験で出たWHEAは、短い負荷を繰り返してもなかなか再現しませんでした。次はAC Load Lineを少し上げて、もう一度FF14を回します。

## AC Load Lineを戻したら、今度はDirectXエラー

AC Load Lineだけを0.300 mΩへ上げ、Point 5・6は−40 mV、Point 7は−80 mVのまま、9月5日の23時半ごろからFF14を回しました。

日付が変わった0時27分、約55分でGPUドライバーのエラーが出ました。画面には「DirectXで致命的なエラーが発生しました。（11000002）」のダイアログ。HWiNFOも続けて落ち、計測が止まっていました。今回はWHEAが出ていません。

ログを調べると、エラー直前に40倍から50倍を含む表示へ変わっていました。やっぱり50倍ではもう少し電圧が必要なのかもしれません。これまでの経緯から、私は引き続きCPU側を疑っていました。

次はAC Load Lineを0.300 mΩのまま、Point 5・6だけを−40から−30 mVへ戻しました。

| Point 5・6 | エラーまでの時間 | 起きたこと |
| --- | --- | --- |
| −40 mV | 約55分 | GPUタイムアウト、DirectXエラー、HWiNFOのクラッシュ |
| −30 mV | 約58分 | GPUタイムアウト、HWiNFOのクラッシュが再発 |

こちらも駄目でした。寝ていたので、止まっているのを確認したのはそのあとです。

今度のエラー直前には、52倍の表示もありました。ここで、CPUを全コア40倍にして、GPUはそのままで試すことにしました。まず高倍率を使わなければ通るのかを見ます。

## 全コア40倍なら、約4時間回った

変えたのは倍率だけです。電圧はAuto、AC Load Lineは0.300 mΩ、Ringは40倍のままにしました。

9月6日の3時47分ごろから回したFF14は、朝になっても動いていました。約3時間52分で止め、停止後までWHEAもGPUドライバーのエラーも出ていません。

これはデカいね。

ここまで動くと、AC Load Lineを0.200 mΩへ下げ直して、40倍をもう少し詰めたくなります。高倍率側にも影響する設定なので、このままにしておくか迷い、今回の電圧の最小と最大を確認しました。

Vcoreは約1.066～1.083 V、平均1.079 V。うーん、十分に低いか。ここをさらに下げるより、残りの倍率を安定させる方を先に進めることにしました。

GPUも設定を変えずにここまで動いたので、そちらへの疑いはかなり薄くなったと思いました。次は1～9コアを50倍、10コアを40倍にします。いきなり52倍まで戻さず、まず50倍との行き来を試す考えです。

## 52倍を外しても、描画の途中で止まる

8時すぎから、50倍と40倍の倍率表でFF14を回しました。

一周したところで、切り替わりのデータを見てもらいました。GPU負荷が落ちる間にCPUが50倍へ上がり、また40倍へ戻っています。周回の境目だけでなく、途中の負荷が落ちるところにも同じような動きがありました。今のところ想定どおりです。

ところが、開始から約20分でGPUのタイムアウトが記録されました。画面を見ると、今回は描画の途中でDirectXエラーになって止まっていました。途中で止まるのは初めてです。WHEAは出ず、HWiNFOの記録は続いていました。

52倍を使わなくても起きる。調べてもらうと、今回もエラー直前に40倍から50倍への変化がありました。

ここでCodexからGPUの設定を緩めて試す案が出ましたが、順番が違うと思いました。GPUはこれまで長時間試験を通っていますし、直前の全コア40倍でも約4時間動いています。まずは今詰めているCPUの電圧を戻して試したい。

Point 5・6の−30 mVをやめ、Autoへ戻しました。50倍／40倍の倍率表、AC Load Line 0.300 mΩ、Ring 40倍は維持しています。

## 50倍の電圧を戻して、もう一度長く回す

過去の測定も見返すと、50倍でFF14を通したときのVcoreには約1.27～1.29 Vの記録がありました。Point 5・6をAutoへ戻した今回が、どのくらいになるかを先に測ります。

9コア50倍、10コア40倍を、それぞれ30秒ずつ測りました。

| 負荷 | Vcore中央値 | 負荷開始直後を含む最小値 |
| --- | ---: | ---: |
| 9コア・50倍 | 1.3054 V | 1.2787 V |
| 10コア・40倍 | 1.0656 V | 1.0656 V |

WHEAは0件。50倍は、立ち上がりの最小値でも以前通ったときの電圧には届いていそうです。40倍の低い電圧も残せています。

次に気になるのは、FF14で短く倍率が切り替わったときにも、このくらいの電圧が出るかです。中央値だけでなく、動いている間の最小値も見ておきたい。9月6日の12時すぎから、この設定でFF14の長時間試験を始めました。

## OCCTは、もっと大きな負荷をかけたくなったときに

動作確認のやり方については、別のチャットでも「みんな電圧設定時の動作確認ってどうやってるの？」と聞いていました。

OCCTなどで試す話が出たので、今やっている負荷のかけ方では駄目なのかと聞き返しました。さらにOCCTとの違いを聞くと、負荷をかけるだけでなく、計算結果が間違っていないかも調べるとのことでした。

それなら使ってみようと話したものの、今もOCCTは一度も使っていません。今の負荷ツールで、欲しい情報は大体取れています。もっと大きな負荷をかけたくなったら、別途試すことになると思います。

まあ、OCCT自体は5年前に入れてあるんですけどねｗ 使い方はすっかり忘れていました。

## 50倍と40倍で、2時間を超えた

この時点で、今回の電圧調整で一番長く回ったのは全コア40倍の約3時間52分でした。倍率を変えながら使った試験では、最初の約1時間47分でWHEAが出た回を超えられていません。そこで、まずはこの50倍／40倍の設定で、2時間エラーなく回ることを目標にしました。

14時すぎ、2時間を超えてもエラーなしという連絡が来ました。

やったね！ ここでFF14を止めました。

最終的には約2時間4分。止めたあとまで確認しても、WHEA、GPUドライバー、アプリのエラーは0件でした。

| 項目 | 平均 | 最大 |
| --- | ---: | ---: |
| CPU温度 | 55.5℃ | 75℃ |
| CPU電力 | 36.3 W | 75.4 W |
| GPU温度 | 64.1℃ | 67.2℃ |
| GPU電力 | 274.2 W | 323.2 W |

冷却水は36℃から43℃へ上がりました。FF14中のVcoreは全体で約1.057～1.305 Vでした。

GPUの設定は変えていません。Point 5・6が−30 mVだった前回は約20分で止まりましたが、Autoへ戻した今回は、周回の切り替わりも含めて2時間を超えました。50倍と40倍を使い分けたまま、まずは目標のところまで回せました。
