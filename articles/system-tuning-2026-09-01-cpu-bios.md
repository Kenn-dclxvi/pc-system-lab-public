# 5.3 GHzを追うところから、5 GHzを実用域にするところへ

[← GPU編](./system-tuning-2026-09-01-gpu.md) / [索引](./system-tuning-2026-09-01-index.md) / [次: エピローグ →](./system-tuning-2026-09-01-ai-agent-epilogue.md)

GPUを1905 MHz / 850 mVまで下げ、FF14を長時間ループさせたところ、約59分でBugCheck 0x50が発生しました。

その約12分前には、CPU/cache側のcorrected WHEAも1件出ています。

GPU温度やGPU driver resetが原因として見えていた825 mV時とは違う落ち方でした。

で、次はCPU側に少し余裕を作ってみることにしました。

ここから、5年前に組んだCore i9-10900KのBIOS設定を、もう一度かなり深く見ることになります。

5年前は、このあたりまで来るとBIOSの項目が多すぎて、仕様を調べても全部は覚えきれませんでした。結局、スコアが出てゲームが安定して動く設定を作ったところで止めています。

今回はAIエージェントに、BIOS設定ファイルの差分確認、計測用スクリプト、ログの集計、WHEAの確認まで任せられます。自分は「次に何を知りたいか」と、出てきた結果を見てどの条件を試すかに集中できました。

## まず最高クロックを100 MHzずつ下げた

当時使っていたTurbo Ratioは、CPUを使っているコア数に応じて、

`53 / 53 / 52 / 51 / 50 / 50 / 49 / 49`

でした。

数字は倍率なので、53なら約5.3 GHz、50なら約5.0 GHzです。

これを全部1段、100 MHzずつ下げました。

| 使用コア数 | 変更前 | 変更後 |
|---:|---:|---:|
| 1 | 53 | 52 |
| 2 | 53 | 52 |
| 3 | 52 | 51 |
| 4 | 51 | 50 |
| 5 | 50 | 49 |
| 6 | 50 | 49 |
| 8 | 49 | 48 |
| 10 | 49 | 48 |

Core/Cache VoltageはManual 1.300 Vのまま。Cache Ratio 43、XMP DDR4-4000もそのままです。

BIOS export同士を比較して、意図した8個のRatio以外に差がないことも確認しました。

まず短いFF14を走らせると、Score差は-0.22%。CPU Package Powerは平均で約3.6 W下がりました。

100 MHz下げた割には、FF14の性能差はほとんどありません。

なら、長時間ではどうなるか。

## 59分で落ちた設定が、3時間22分通った

同じ設定でFF14の長時間ループを行いました。

結果は3時間22分37秒。

- WHEA: 0
- `nvlddmkm`: 0
- LiveKernelEvent 141: 0
- BugCheck: 0
- Application Error / Hang: 0
- CPU thermal throttling / power limit: 0

CPU最大77℃ / 109.2 W。Liquidは45℃まで上がり、最後の30分を平均45℃で維持しました。

前回は約59分で落ちています。今回はその約3.43倍の時間を継続しました。

CPUの最高クロックを全体に100 MHz下げたことで動作に余裕ができ、安定性が改善した可能性は高そうです。

ただし、前後の試験ではGPU側の保存プロファイルにも差があります。なので「CPU Ratioだけが原因だった」とまでは言いません。

観測として言えるのは、**この設定ならFF14を3時間22分以上、エラーなしで回せた**ところまでです。

普通ならここで終わってもよかったと思います。

性能差はほとんどなく、長時間安定した。

ただ今回は、せっかく詳細なログを取れるようになっています。

で、「そもそも5.3 GHzって普段どれくらい使っているんだ？」が気になりました。

## 100 MHz下げたけれど、そもそもFF14では5.3 GHzが出ていなかった

CPU RatioをAutoへ戻し、Intel本来のTurbo Boost、Turbo Boost Max Technology 3.0、Thermal Velocity Boostを使う状態へ戻しました。

Thermal Velocity Boost、TVBは、CPU温度などに余裕があるときに追加でクロックを上げるIntelの仕組みです。

10900Kでは条件が揃うと最高5.3 GHzまで上がります。

そこでFF14中の各コアのクロックを記録しました。

結果、5.3 GHzは一度も出ませんでした。

HWiNFOが保持しているMaximum履歴まで確認しても53倍は0回。各コアの最大は49～50倍でした。

CPU Total Usageは平均18.5%ですが、FF14は複数のコアを継続して使っています。

10900Kの5.3 GHzは、1～2コア程度しか使わない軽い負荷で、さらに条件のいいコアが選ばれたときの最高動作点です。

だとすると、FF14で出ないこと自体は不思議ではありません。

なら逆に、5.3 GHzが出る条件をこちらから作ってみることにしました。

## Preferred Coreを狙うと、本当に5.3 GHzが出た

Windowsの通常処理や計測処理をなるべく別のコアへ寄せ、負荷を特定の物理コアへ固定しました。

さらに試験中だけcore parkingを使い、動くコア数を少なくします。

するとP-Core 2が5,298.728 MHzへ到達しました。

同じ方法でP-Core 0 / 1 / 4～9も全部試しましたが、こちらは最大約5.10 GHzです。

最後に同じ条件でP-Core 2をもう一度試すと5.3 GHzへ到達しました。

つまり、5.3 GHz機能そのものは正常です。

ただ、どのコアでも出るわけではなく、Preferred Coreと呼ばれる選別されたコア側で、少数コア負荷などの条件が揃ったときだけ出る。

こういう試験は1回なら手でもできます。ただ、非Preferredの8コアを順番に試し、毎回ログとWHEAを確認し、最後にP-Core 2を同じ方法でもう一度測るところまでやると急に面倒になります。今回はその繰り返しをAIエージェントへ任せられたので、「5.3 GHzが出た」で終わらず、どのコアで出るのかまで確認できました。

ここで5.3 GHzの見方が変わりました。

最高スペックとしては5.3 GHzですが、FF14のような実負荷で長く使っているのは4.9～5.0 GHz付近です。

ただ、この時点で5.3 GHzを捨てるとは決めませんでした。

5.3 GHzはそのまま残し、まずFF14で長く使っている4.9～5.0 GHz付近の電圧を下げられないかを見ることにしました。

## 固定1.3 Vから、負荷に合わせて電圧を変えるAdaptiveへ

5年前はCore/Cache VoltageをManual 1.300 Vにしていました。

これは分かりやすく、安定もさせやすい一方で、負荷が軽いときも基本となる電圧設定を固定します。

そこでAdaptive Modeへ戻しました。

Adaptiveは、CPUが必要とするクロックに合わせて要求電圧を変える方式です。

FF14はWHEAなしで完走しました。

次に気になったのは、Autoが実際にどれくらい電圧を入れているかです。

ASUS BIOSにはV/F Pointという設定があります。

簡単に言えば、特定のクロック付近で使う電圧を個別に増減できます。

まずPoint 5とPoint 6を各-30 mVにしました。

FF14で主に使っていた4.9 GHz付近を見ると、実測Vcoreも約30 mV下がりました。

かなり素直に効いています。

そこで-40 mVへ進みました。

## -40 mVで3時間31分

Point 5 / 6を各-40 mVにして長時間FF14ループを行いました。

GPU負荷中で3時間31分46秒。

WHEA、BugCheck、GPU driver / application failure、thermal limit、power limitはすべて0です。

CPU負荷中の平均Powerは、

- Adaptive補正なし: 83.479 W
- P5/P6 -40 mV: 79.240 W

まで下がりました。

電圧調整はきちんと効いています。

ただ、以前のManual 1.300 V長時間試験は76.788 Wでした。

Adaptiveの利点を残しながらかなり近づいたものの、まだ固定1.300 Vより少し高い。

ここで一度考え直しました。

BIOSへ「1.300 V」と入力したことと、ゲーム中にマザーボード側で実際に観測するVcoreは同じではありません。

だったら昔のManual 1.300 Vをもう一度同じ計測系で動かして、実測値を基準にすればいい。

ファン調整で一度100%を測ってから必要量へ戻したのと同じ考え方です。

固定電圧へ戻りたいわけではありません。

**固定電圧で成立していた実際の動作点を測り、それをAdaptive側の参考にする**ことにしました。

## その前に倍率ごとの電圧を測った

Point 5を-50 mV、Point 6を-40 mVへ変更し、同時に動く物理コア数を制御しながら倍率ごとのVIDとVcoreを取りました。

VIDはCPUが要求している電圧、Vcoreはマザーボード側で観測した実際のCPU電圧です。更新タイミングも意味も少し違うので、同じ数字としては扱いません。

短時間試験では、49、50、51、53倍を取得できました。

52倍だけは条件を変えても観測できず、Missing Dataのまま残しました。

主なVID中央値は、

- 49倍: 1.205688 V
- 50倍: 1.261841 V
- 51倍: 1.293457 V
- 53倍: 1.400146 V

でした。

53倍へ行くと電圧がかなり跳ねます。

ただし、それぞれ負荷条件が違うので、この4点をそのまま一本のきれいなV/F Curveとして結ぶことはしません。

それでも、5.3 GHzがかなり上端側の動作点であることは実測でも見えてきました。

## ASUSのOverclocking TVB +1も試した

このあたりでASUSの`Overclocking TVB +1Boost Profile`を試しました。

温度などに余裕があるとき、通常より100 MHz高い倍率を使わせる機能です。

最初はかなり良さそうに見えました。

普段4.9 GHz、余裕があれば5.0 GHz。

固定5 GHzより自然に使えそうです。

ただ、+1されるのは実用域だけではありません。

最上端も上がるので、もともと5.3 GHzだった側には5.4 GHzという条件が加わります。

Preferred Coreを使った短時間試験ではWHEAが出ました。

最初はV/F Pointを下げすぎたせいかもしれないと考えました。

そこでPoint 1～8を全部Autoへ戻して再試験しました。

それでもP-Core 2の短時間試験開始直後にcorrected cache / instruction-execution WHEAが再現しました。

なので、少なくともV/F Pointのマイナス補正だけが原因とは言えません。

こちらが欲しいのは5.4 GHzではありません。

欲しいのはゲーム中に長く使う5.0 GHzです。

ということで、+1Boostを追うのはやめました。

## 最高速ではなく、実用側を5 GHzへ底上げする

ここで方向を変えました。

5.3 / 5.4 GHzを追うのをやめ、使用コア数が多いときの倍率を直接5.0 GHzへ上げます。

新しいRatioは、

`52 / 52 / 51 / 50 / 50 / 50 / 50 / 50`

です。

つまり、

- 1～2コア使用時: 5.2 GHz
- 3コア使用時: 5.1 GHz
- 4～10コア使用時: 5.0 GHz

とします。

最高5.3 GHzや5.4 GHzを追うのではなく、FF14のような実負荷で長く使う側を5 GHzへ持ち上げる。

最高速より、実用回転域のトルクを太くする感じです。

## まず昔と同じManual 1.300 Vで5 GHzを測る

最初はCore/Cache VoltageをManual 1.300 Vに戻して、新しい倍率表だけを試しました。

FF14は完走しました。

全10コアで50倍、5.0 GHzを確認しています。

Scoreは17,448。

CPU平均Powerは85.00 W、平均温度61.38℃。

そして50倍時のmotherboard Vcore中央値は**1.269853 V**でした。

BIOSには1.300 Vと入っていますが、FF14中に観測したVcore中央値は約1.27 Vです。

これでManual 1.300 Vは昔の設定ではなく、**このCPUが5 GHzのFF14負荷で成立していた基準データ**になりました。

## Adaptive Autoにすると約1.41 Vまで上がった

次は倍率表をそのままにして、電圧だけAdaptive Autoへ戻しました。

FF14は完走し、Scoreは17,552。

Manualの17,448より+0.596%ですが、各1回の測定なので、この差を設定による性能向上とは考えません。

それより大きかったのは電圧です。

50倍時のVcore中央値は、

**1.269853 V → 1.411934 V**

へ上がりました。

CPU平均Powerも、

**85.00 W → 103.77 W**

平均温度も、

**61.38℃ → 70.33℃**

です。

性能差は小さいのに、電圧、電力、温度には大きな差があります。

Autoは幅広い個体を安定させるために、安全側へかなり余裕を持たせているのかなと思います。

でもこの個体はManual 1.300 Vで5 GHzを動かした実測値があります。

なら、その差をV/F Pointで削ってみます。

## Adaptiveを残したまま、5 GHzを約81 Wまで下げた

次の設定は、

- V/F Point 4: -50 mV
- Point 5: -100 mV
- Point 6: -100 mV
- Point 7: -100 mV
- 全体Offset: Auto
- Core/Cache Voltage: Adaptive Mode

です。

CPU全体へ一律に-100 mVを掛けたわけではなく、5 GHz前後で使うV/F Pointを中心に下げています。

FF14は完走しました。

全10コアで5.0 GHz。

Scoreは17,524です。

Adaptive Autoの17,552との差は-28、-0.160%。

一方、50倍時のVcore中央値は、

**1.411934 V → 1.296493 V**

CPU平均Powerは、

**103.77 W → 81.25 W**

平均温度は、

**70.33℃ → 63.85℃**

まで下がりました。

WHEA、BugCheck、GPU driver / application failure、thermal limit、power limitはいずれも0です。

さらにManual 1.300 V時の平均Powerは85.00 Wでした。

今回の1回の測定では、**5 GHzを全10コアで使いながら、昔の固定1.300 Vより平均Powerを3.74 W下げた**ところまで来ています。

## 5.3 / 5.4 GHzを追わず、4～10コアを5 GHzにした

最初にWHEA対策でTurbo Ratioを全段100 MHz下げたときは、単純に最高クロック側を下げて長時間安定するかを見ていました。

その後、5.3 GHz自体はPreferred Coreで正常に動くことが分かり、しばらくは5.3 GHzを残したままV/F Pointだけを下げています。

さらにOCTVB +1も試しましたが、こちらは5.0 GHz側だけでなく5.4 GHz側まで対象になり、全V/F PointをAutoへ戻しても短時間WHEAが再現しました。

そこで5.3 / 5.4 GHzを追うのをやめ、1～2コア時は5.2 GHz、3コア時は5.1 GHz、4～10コア時は5.0 GHzとしました。

そのうえで、5.0 GHz付近へAdaptive Autoが入れていた電圧をV/F Pointで下げました。

5年前は「5 GHzでゲームができればいい」で終わりました。

今回は、同じ5 GHzでも、どの条件で使い、何V掛かり、何W使っているかまで測れるようになりました。

## 次は5.1 / 5.2 GHzと長時間5 GHz

ただ、まだ完成ではありません。

最新設定でFF14を1回完走したことは確認できていますが、長時間試験はまだです。

またFF14ではほぼ50倍だけを使っていたので、軽い負荷で使う5.1 GHz、5.2 GHz側も別に確認する必要があります。

なので次は、まず51倍と52倍の短時間試験です。

そこでCPU内部エラーが出ないことを確認したあと、5.0 GHz設定のままFF14を数時間回します。

Liquidが熱平衡まで上がったあとも、Vcore、CPU Power、温度、WHEAが安定していれば、そこで常用設定としてかなり自信を持てます。

最高クロックを追うより、使うところを太くする。

この10900Kでは、今のところその方向がかなり良さそうです。
